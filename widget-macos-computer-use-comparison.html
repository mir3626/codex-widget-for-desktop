Codex Widget vs macOS Computer Use

현재 저장소 구현 상태를 기준으로, macOS에서 기대되는 일반적인 Computer Use 기능과 비교한 표입니다. 여기서 macOS Computer Use는 화면 캡처, 좌표 기반 클릭/타이핑/스크롤/키 입력, 대기, 반복 스크린샷 피드백 루프를 갖춘 로컬 macOS 또는 VM 기반 computer-use 환경을 의미합니다.

구현됨 현재 위젯에서 바로 쓰거나 smoke가 있는 기능
조합 가능 단일 파이프라인은 아니지만 모듈 조합으로 구현 가능한 기능
부분 구현 기반은 있으나 실제 macOS 수준 연속 workflow에는 추가 연결 필요
제한/미구현 안전, OS 권한, signing, helper 부재 등으로 아직 제한

핵심 차이: macOS Computer Use는 보통 "모델이 화면을 보고 다음 좌표/키보드 액션을 계속 제안하고, 런타임이 실행 후 스크린샷을 다시 보내는" 하나의 폐루프가 중심입니다. 현재 위젯은 이 폐루프를 단일 OS 파이프라인으로 완성했다기보다는, Browser Action, Vision/OCR, Terminal, capability runtime, Toolsmith, eval ledger 등 여러 모듈을 갖추고 있고 이를 조합하면 상당수 workflow를 구현할 수 있는 구조입니다.

Capability Matrix

기능 영역 macOS Computer Use 기준 기대 기능 현재 위젯 상태 위젯 구현/조합 방식 차이와 후속 작업
전체 실행 루프 스크린샷 입력 → 모델 액션 제안 → OS가 클릭/타이핑/스크롤/키 입력 실행 → 새 스크린샷 반환을 반복하는 폐루프. 조합 가능
  • screen_observe, ocr, desktop_action, browser_action, capability DAG를 조합.
  • eval ledger가 run/step/evidence/latency를 기록.
  • Browser Action에는 prompt-driven plan/execution/verification 루프가 있음.
 OS 전체를 대상으로 하는 단일 "CUA loop"는 아직 아님. DAG scheduler가 관찰/계획/승인/액션/검증을 묶지만 macOS용 input executor와 screenshot feedback loop가 추가로 필요.
브라우저 DOM 탐색 화면 기반 탐색이 기본이며, 환경 구현에 따라 DOM/Playwright 접근도 가능. 구현됨
  • Chrome/Edge MV3 Browser Bridge extension이 active tab DOM snapshot 수집.
  • Browser Action target selection, semantic live corpus, perception graph로 연결.
  • 관련 경로: providers/browser-dom-extension, src/daemon/browser-action.
 macOS에서도 Chrome/Edge extension은 재사용 가능. Safari 지원은 별도 extension/native integration 필요.
브라우저 페이지 조작 click, type, scroll, keypress, wait, screenshot 등 화면 액션 중심으로 페이지를 조작. 구현됨
  • Extension action channel: read/evaluate/navigate/back/forward/reload/scroll/click/type/select/check.
  • CDP adapter와 Playwright adapter도 보유.
  • 위험 액션은 approval/verification 경로를 통과.
 화면 좌표 기반 universal action보다 DOM/selector 기반 성공률이 높은 대신 restricted page나 browser chrome UI에는 제한이 있음.
브라우저 Chrome 제어 주소창, 탭, 다운로드, 브라우저 UI, 파일 업로드 등도 화면 조작으로 접근 가능. 구현됨
  • browser_chrome capability가 bookmarks, tab groups, downloads, history, debugger, file upload commands 지원.
  • tab group claim/release, download start/observe/verify/cancel, one-time history, bounded debugger, DOM.setFileInputFiles 기반 upload.
  • 관련 경로: src/daemon/browser-chrome, providers/browser-dom-extension/bridge/browser-chrome.js.
 Chrome/Edge extension API 기반이라 브라우저별 권한과 store review가 필요. History/debugger/file upload는 항상 승인 필요.
Restricted page 처리 화면 좌표 방식이면 chrome:// 같은 페이지도 시각적으로는 볼 수 있으나 정책상 제한 가능. 부분 구현
  • Extension은 restricted page를 명시적으로 unsupported/permission-needed로 보고.
  • Browser Action recovery UX와 blocker evidence가 있음.
  • Windows native helper fallback은 browser window observe/read/reload 일부 가능.
 macOS 수준의 browser chrome fallback에는 Accessibility/Screen Recording 기반 native helper가 필요.
화면 캡처 현재 화면 또는 VM 화면을 캡처해서 모델에 제공. 구현됨
  • Vision snapshot, Agent screen share, Windows screen capture helper.
  • hash/diff/meaningful-change metadata와 blob storage 사용.
  • 관련 경로: providers/screen-capture-helper, src/daemon/providers/screenCaptureProvider.ts.
 현재 구현은 Windows-first. macOS는 screencapture, ScreenCaptureKit, TCC Screen Recording 권한 처리가 필요.
OCR / 시각 인식 스크린샷에서 텍스트와 UI 요소를 읽고 다음 행동을 결정. 구현됨
  • OCR capability, bundled Tesseract discovery, ROI/delta cascade planning.
  • PerceptionGraph가 DOM/UIA/OCR/screenshot evidence를 통합하는 substrate.
  • 관련 경로: src/daemon/perception-graph, src/daemon/perception-cascade.
 macOS용 OCR runtime 자체는 이식 가능하지만, native accessibility evidence는 AX API adapter가 필요.
마우스/키보드 OS 입력 좌표 클릭, 더블클릭, 드래그, 키 입력, 단축키, 스크롤 등 OS 입력 실행. 부분 구현
  • Browser Action에서는 extension/CDP/Playwright/native helper를 통해 click/type/scroll 가능.
  • Windows native desktop helper가 bounded browser-window actions 지원.
  • Terminal PTY에는 direct input/key/mouse forwarding 구현.
 macOS 전체 OS 입력에는 Accessibility permission, CGEvent, AX action helper, hardened runtime/notarization 설계가 필요.
네이티브 앱 조작 Finder, System Settings, 앱 메뉴, 파일 대화상자 등 일반 앱 UI를 조작. 제한/미구현
  • 현재 native helper는 Windows UI Automation 기반 bounded browser/window fallback 중심.
  • Windows Settings dogfood matrix는 read/reversible/blocked workflow evidence를 기록.
 macOS native app control은 새 helper가 필요. AX tree observe, menu bar control, Finder/file picker scope, TCC permission UX, signing/notarization이 핵심 blocker.
파일 시스템 작업 사용자 허용 범위 안에서 파일 생성, 열기, 변환, 저장, 업로드/다운로드 검증. 구현됨
  • Artifact/blob storage, terminal capability, scoped autonomy permission profiles.
  • Toolsmith web_research_to_pdf, local document conversion fallback, browser download verifier.
  • Browser file upload은 explicit approvedFilePaths만 허용하고 evidence redaction.
 macOS Finder/file picker UI 조작은 별도. CLI/daemon 파일 생성과 브라우저 upload path는 구현됨.
터미널 작업 필요 시 shell command 실행, 결과 관찰, 파일 생성/변환/검증. 구현됨
  • One-shot terminal capability와 persistent node-pty/ConPTY PTY session.
  • Renderer terminal viewport, raw input, key, mouse forwarding.
  • Credential-like terminal command rejection과 destructive guard 있음.
 macOS shell 자체는 이식 가능성이 높지만 PTY packaging/runtime과 destructive command policy를 macOS release 경로에 맞춰 검증해야 함.
음성/ASR 입력 컴퓨터 사용 요청을 음성으로 받아 명령/슬롯으로 변환 가능. 구현됨
  • ASR sidecar abstraction, faster-whisper/whisper.cpp/Vosk candidates, persistent worker.
  • Deterministic command-slot decoder, lexicon/alias, clarification gate.
  • GPU validation과 human mic corpus는 deferred.
 macOS microphone permission/TCC와 local model runtime packaging 검증 필요. 현재 CPU-first evidence 중심.
자기 구현 / Toolsmith 기본 computer-use 액션으로 부족한 작업을 local tool/script로 보완할 수 있음. 구현됨
  • Scoped autonomy profiles, gap detector, capability inventory, generated tool manifest.
  • Materialize → smoke → retry/revise → activate → execute → rollback/debug bundle.
  • 대표 slice: live web research to Markdown/PDF, safe terminal generated tool, download verifier.
 무제한 YOLO가 아니라 scoped YOLO. macOS에서도 동일 원칙으로 command/path/domain/risk grant가 필요.
승인/안전 정책 민감 사이트, 인증, 결제, destructive action, prompt injection 위험에 human-in-the-loop 적용. 구현됨
  • Capability runtime approval, Browser Action approval cards, scoped autonomy permission profiles.
  • History/debugger/file upload one-time approval, credential redaction, restricted-page blockers.
  • Terminal credential-like command persistence 거부.
 macOS native helper 추가 시 Screen Recording/Accessibility 권한 자체도 사용자 승인 UX에 포함해야 함.
평가/증거 기록 반복 실행 성공률, latency, action trace, screenshot evidence, verifier 결과를 기록. 구현됨
  • Unified computer-use eval ledger schema v4.
  • Browser/Windows/ASR/Vision/Terminal/cross-app run/step/resource 기록.
  • Debug bundle, rollup, dogfood reports, real widget session audit script.
 macOS executor가 들어오면 같은 eval ledger에 macOS modality와 native helper evidence를 연결하면 됨.
성능 최적화 화면 변화가 없으면 비싼 OCR/VLM 재실행을 줄이고, p95 latency를 관리. 구현됨
  • Screenshot tile hashing, dirty-region planning, ROI OCR capability path.
  • Cascade stages: cache/DOM/UIA/tile diff/ROI OCR/detector/parser/VLM fallback planning.
  • Stage latency와 p50/p95 metric rollup 기반.
 VLM fallback provider는 완전한 live provider로 더 연결해야 함. macOS 화면 캡처 source가 들어와도 cascade 구조는 재사용 가능.
실패 메모리 반복 실패 패턴을 학습해 다음 후보 선택, 복구, abstention에 반영. 구현됨
  • Structured failure memory, taxonomy, calibration updater.
  • Memory는 현재 UI proof가 아니라 ranking/calibration hint로만 사용.
 macOS UI 패턴 전용 실패 taxonomy와 AX/visual evidence provenance를 추가하면 확장 가능.
다운로드/문서화 workflow 웹 조사, 다운로드, 문서 생성, PDF 저장 같은 end-to-end task 수행. 구현됨
  • Scoped autonomy live web research/PDF vertical slice.
  • Browser download verify, Markdown/PDF artifact generation, source/evidence/debug bundle.
  • Terminal/pandoc 등 허용 command가 있으면 document conversion helper로 확장 가능.
 UI를 클릭해 수행하는 macOS CUA 방식보다, 현재 위젯은 tool/direct HTTP/terminal 경로를 함께 써서 더 안정적인 path를 선택할 수 있음.
앱 전환/윈도우 관리 Dock, Mission Control, 앱 전환, 창 포커스/이동/크기 조절 가능. 제한/미구현
  • 위젯 자체 window/tray/start-at-login은 구현됨.
  • 일반 OS window control은 Windows helper도 browser-window scoped 중심.
 macOS AX/CGWindow 기반 window enumerator, focus, move/resize, app launch helper가 필요.
인증/쿠키/비밀정보 인증된 환경에서 작업할 수 있지만, 안전상 높은 감독과 제한이 필요. 제한/미구현
  • Credential storage/access는 명시적으로 구현하지 않음.
  • OAuth/Codex auth token은 renderer에 노출하지 않고 daemon memory boundary 유지.
  • Authenticated browser profile/cookie access는 external blocker로 관리.
 macOS Computer Use에서도 credential entry/2FA/payment는 human-in-the-loop가 필요. 위젯은 기본적으로 credential secrecy를 우선.
릴리즈/권한 배포 macOS 앱은 Screen Recording/Accessibility 권한, notarization, hardened runtime, helper signing이 중요. 부분 구현
  • Windows MSI/NSIS, bundled daemon/node/OCR/PTY runtime, browser extension store packet 구현.
  • Windows native helper signing readiness는 있으나 production certificate/service는 blocker.
 macOS release를 하려면 Tauri macOS bundle, notarization, AX helper entitlement, TCC onboarding, helper update/signing policy가 새로 필요.
사용자 관찰 UI 작업 중인 액션, 안전 체크, 결과를 사용자가 감시하고 중단할 수 있어야 함. 구현됨
  • Capability Jobs panel, Activity ledger, approval/cancel controls.
  • Autonomy Toolsmith panel, debug bundle copy/save, Browser Action diagnostics.
  • Vision sharing overlay와 stream state 표시.
 macOS full CUA loop가 들어오면 좌표 액션/스크린샷 preview/stop button을 같은 panel에 연결하면 됨.

Pipeline 조합 예시

사용자 요청 유형 현재 위젯 조합 방식 macOS CUA 방식과의 차이
웹에서 자료 조사 후 PDF 생성 scoped autonomy profile → gap detector → Toolsmith web_research_to_pdf → live fetch/extract/citation → Markdown/PDF artifact → eval ledger. 화면 클릭으로 브라우저를 조작하기보다 허용 domain HTTP/tool path를 우선 사용해 재현성과 속도를 높일 수 있음.
브라우저에서 파일 다운로드 후 검증 browser_chrome download.start → download.observe → download.verify → artifact/evidence 기록. macOS CUA는 다운로드 UI를 시각적으로 추적할 수 있으나, 위젯은 extension API로 더 구조적인 evidence를 얻음.
화면의 특정 텍스트/버튼 인식 후 클릭 screen_observe + OCR/perception graph → target explanation → desktop_action 또는 Browser Action 실행 → verifier. 현재 OS 전체 클릭 executor는 Windows/browser 범위가 강함. macOS는 AX/CGEvent helper가 필요.
브라우저 업로드 폼에 파일 지정 file_upload.inspect → approval with explicit approvedFilePaths → file_upload.set_files → 필요 시 file_upload.clear. macOS CUA는 파일 선택 창을 직접 조작할 수 있지만, 위젯은 path grant 기반으로 브라우저 input에 직접 파일을 지정.
터미널 기반 로컬 작업 terminal capability 또는 PTY session → output stream → artifact/eval 기록 → destructive/credential guard. macOS CUA가 Terminal.app을 화면으로 조작하는 대신, 위젯은 daemon PTY/child process를 직접 관리.

위젯 / Codex macOS Computer Use / Hermes Agent Computer Use 수행 가능성 비교

실제 사용자가 한 번에 입력할 법한 프롬프트를 기준으로, 현재 로컬 위젯과 공개 문서상 Codex macOS Computer Use, Hermes Agent Computer Use가 어디까지 수행 가능한지 비교했다. 이 문서는 기능 홍보가 아니라 “실제 수행 가능 여부”와 “필요 조건 / 차단 조건”을 구분하는 벤치마크다.

핵심 결론

Codex Widget for Desktop

현재 구현은 Windows 로컬 위젯 기준으로 브라우저 DOM/Chrome 제어, terminal, Toolsmith, Computer Session DAG, evidence/debug bundle이 강하다.

  • 강점: auditable Browser Action, Browser Chrome tab.activate, 다운로드/권한/히스토리 일부, terminal/toolsmith, redaction/eval evidence.
  • 조건부: Gmail 같은 로그인 웹 UI는 사용자가 이미 로그인했고 Browser Bridge 권한을 부여해야 한다.
  • 약점: 임의 native app 조작, foreground input, 파일 피커, 권한 팝업 native click, VM execution은 guarded/deferred.

Codex macOS Computer Use

OpenAI 공개 설명상 background computer use로 macOS 앱을 보고, 클릭하고, 타이핑할 수 있으며 별도 cursor로 병렬 작업이 가능하다.

  • 강점: 일반 macOS 앱/브라우저 UI를 사람처럼 조작하는 범용성, 병렬 agent, 앱 내 browser, Codex skills/plugins/automations.
  • 조건부: 인증/개인정보/구매/파괴적 작업은 사용자 로그인과 승인, 안전 경계가 필요하다.
  • 약점: 공개 문서만으로는 특정 웹사이트별 성공률과 enterprise policy 세부 동작을 확정할 수 없다.

Hermes Agent Computer Use

Hermes 공식 문서상 macOS cua-driver를 통해 background desktop 제어가 가능하고, 별도 browser automation toolset도 제공한다.

  • 강점: Mail/Safari 같은 macOS 앱 background 조작, SOM 번호 기반 capture, Playwright/CDP/cloud browser backend.
  • 조건부: macOS Accessibility/Screen Recording 권한, driver 설치, browser session/cookie 준비가 필요하다.
  • 약점: macOS driver는 Apple private SPI 변경 위험이 있고, SOM element index는 capture 후 state change 때 stale해진다.

상태 표기

가능 일반 설정에서 end-to-end 수행 가능성이 높음 조건부 로그인/권한/사용자 승인/환경 준비가 필요 부분 쪼갠 프롬프트나 수동 보조가 있으면 가능 차단 현재 정책/환경/구현상 수행하면 안 됨 비주력 해당 제품의 주 기능면이 아님
중요: “가능”은 계정 로그인, 네트워크, 사이트 레이아웃, CAPTCHA, 2FA, OS 권한, 사용자 승인 같은 현실 조건이 정상이라는 뜻이다. 민감한 메일/세금/금융/계정 작업은 자동 수행 가능성보다 안전 승인 경계가 우선이다.

대표 예시: “gmail열어서 국세청에서 온 종소세 관련 이메일 내용 확인해줘”

Codex Widget for Desktop 조건부 / 중간 신뢰브라우저가 이미 로그인된 Gmail 세션을 갖고 있고 Browser Bridge 권한이 있을 때 가능성이 있다. Codex macOS Computer Use 조건부 / 높은 신뢰background computer use가 browser 또는 Mail 앱 UI를 직접 조작할 수 있다는 공개 설명에 부합한다. Mac에서 Chrome/Safari/Gmail 또는 Mail 앱을 열고 검색, 메시지 선택, 본문을 읽어 요약. 필요하면 own cursor/background 방식으로 사용자의 작업과 병행. macOS Computer Use 사용 가능 지역/계정, 앱 권한, 로그인/2FA, 민감한 세금 메일 열람 승인 필요. 구매/제출/삭제 같은 irreversible action은 human-in-loop가 필요하다.
Hermes Agent Computer Use 가능 / 높은 신뢰공식 문서의 quick example이 “최신 Stripe 이메일 검색/요약”과 거의 동일한 Mail workflow다. macOS Mail 앱을 SOM capture로 읽고 검색 필드 클릭, from:국세청 종소세류 검색, 결과 선택, 본문 요약. Gmail web은 browser automation/CDP로도 가능. macOS, cua-driver, Accessibility/Screen Recording 권한, Mail 또는 browser 로그인 필요. capture 후 element index stale 문제로 재-capture 루프가 필요할 수 있다.

해석 가이드

  • 위젯은 브라우저/Chrome/terminal/evidence형 작업에 강하다. 특히 로컬 evidence와 redaction, permission profile, debug bundle이 필요한 검증형 작업은 비교 우위가 있다.
  • Codex macOS와 Hermes는 범용 desktop 조작에 강하다. 앱을 직접 보고 클릭/입력해야 하는 일반 macOS 앱 작업은 현재 위젯보다 수행 가능성이 높다.
  • Hermes는 Mail 예시와 browser toolset이 명확하다. 공식 문서상 이메일 검색/요약 예제가 있어, Gmail/Mail류 작업은 macOS 설정만 맞으면 높은 신뢰로 평가한다.
  • 민감 인증 흐름은 세 제품 모두 “자동화 가능성”보다 “승인 경계”가 우선이다. 로그인, 세금, 결제, 계정, 권한 변경, 제출은 사용자의 명시 승인과 rollback/감사 기록이 있어야 한다.
  • Max Spec은 제품의 상한선을 보는 벤치마크다. 일반 사용자가 자주 요청하지 않아도, 여러 기능을 조합하면 실제로 시도 가능한 복합 task를 포함했다.
